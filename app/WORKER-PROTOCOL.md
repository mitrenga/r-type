# Worker protocol

The main thread draws, the worker holds the world. Messages are all that
joins them. State as of M6 (2026-10-18): the worker has the clock, the source
of randomness, the joystick, space and F7, **the level** scrolled by the
original's code (`app/levelScroll.js`), **the ship with all its weapons, the
panel and the sprites** (`app/ship.js`), **the enemies, waves, multiplexer and
bosses** (`app/enemies.js`, `app/levelCode.js`), **the main loop around the
level** (`app/gameRules.js`): READY with fire, losing a life and restarting
from the checkpoint, the end of a level and loading the next, GAME OVER —
and from M6 **the SID player** of the level's file `M` (`app/sidPlayer.js`):
music and effects alike are **a sequence of stores into `$D400`–`$D418`**
that the worker reports for every frame and the main thread hands to the
chip model in the worklet (`app/audioManager.js`, R-040, R-044).

## Main thread → worker

| message | fields | what it does |
|---|---|---|
| `init` | `seed`, `levels`, `level`, `immortal`, `panel`, `ship`, `sprites`, `enemies`, `charsets`, `music` | sets up the world: `levels` is all eight records of `data/levels.json` (the worker takes the further levels after a boss from them too — a stand-in for loading on from the tape), `level` the number 1–8 of the level the game starts in (a level record instead of a number = a single level, the M2–M4 tools); the worker builds the map with the routine `$162F` and runs the original's init `$0818` → `$088A` up to **READY** (`Ship.init`); `panel` is rows 19–24 of Screen RAM and Color RAM as the original's init leaves them (`{screen, color}`, 240 cells, composed by `app/levelLoader.js`); `ship` and `sprites` are `data/ship.json` and `data/sprites.json`; `seed` is the seed of the **seeded generator** (a 16-bit LFSR) that stands where the original reads `$DC04`, and from which the death → READY race is drawn too (`GameRules.raceWait`); `immortal` (optional) switches on the harness patch `$319C` = RTS, the ship does not die — in the browser only `?devImmortal=1` in `$devMode`; `enemies` is `data/enemies.json`; `charsets` is `data/charsets.json` — each level's upper set lies in `ram` at `$86AC` (the start of file `G`, from where `$11FA` copies it to `$C000`) and the lower one in `high` at `$E000` (the start of `S`, only as many bytes as the file has); **`music`** is `data/music.json` (M6) — the player's variables and each level's song `$637F`–`$7ABF` from file `M`, copied into `ram` with every level load so that the player starts a level as the original does; clears the frame and the input; answers `ready` |
| `start` | — | starts the clock, 50 Hz (a PAL frame), `setTimeout` with an accumulator (R-046) |
| `stop` | — | stops the clock (pause, the tab losing focus, leaving the model) |
| `continue` | — | ★ **the remake's continue** (`ZADANI.md` §10.7): the world stands on the REWIND screen after GAME OVER; clears the score (`$338B`–`$3390`), gives three lives back (`$281D`), drops the flag `$281F`, starts the level's tune as the level init does and goes to READY with a restart from the checkpoint a lost life would return to (`GameRules.continueGame` → `restartCode`, `$08F5`); answers `continued`, or `continueFailed` when the world is not standing on REWIND (the main thread then sets up a new game through `init`) |
| `input` | `joystick`, `space`, `f7` | `joystick` is the byte `$DC00` would give — port 2, **active low** (the ship step `$2824` and fire on READY `$0C27` read it); `space` is the space bar the original reads from the keyboard matrix (`$2A2A`, `$2AB0`): detaches and recalls the Force; `f7` is the original's F7 (`$0E96`): pauses the game, fire cancels it (`$0E8A`) |
| `random` | — | one value from the source of randomness; answers `random` |
| `sample` | `music`, `level`, `frames`, `kind`, `effects` | M6: a sample for the volume dialog — **the start of the tune of level** `level` played by the same player over a scratch memory (`$637C` with `$6D40`, `$6379` with 3, `frames` steps, then `$6373`); with `effects` (numbers from the table `$3413`) also one effect on voice 2 every 40 frames as `Ship.sound` does (`$63C1`/`$63C2`) and the voice roles in the script as pseudo-registers `$20`+voice of the SID model (R-055); `kind` (`music` / `sounds`) comes back in the `sample` answer; `kind` = `title` plays **the original's title tune** (`music.title`: the song at its own addresses `$71D0`–`$7FFF` over level 1's player, table `$71D0`, tune 2) **once**, until the sequence returns to the loop (`SidPlayer.onLoop`), at most `frames` (10 000) frames; ★ one pass = 6 528 frames — ABOUT |

| message | fields | what it means |
|---|---|---|
| `ready` | `seed`, `level` | the world stands, the clock is not running yet |
| `frame` | `frame`, `joystick`, `space`, `level`, `mode`, `state`, `score`, `lives`, `events`, `over`, `screen`, `color`, `fine`, `fineY`, `pointer`, `running`, `reg64`, `vic`, `sprites`, `glyphDD`, `lifeOver`, `gameOver`, `levelOver`, `bands`, `boss`, `high`, `sid`, `sidRoles`, `canContinue` | a PAL frame has passed (`GameRules.frame`): in play the original's interrupt chain (`Ship.frame`: raster 48 — blinking, the scroll step, the sprite loop `$17FB`; band 5 — the spawner and the enemies' state machine; raster 202 — the bits into the sprite, the score, 1UP, the game step `$3D74`, the ship step `$2821` or the death animation `$31FC`, the level hook; between them the main loop `$08C1`), otherwise one READY iteration (`$0BF8`), a restart frame (the init with the nested handlers) or one iteration of the sequence after a level (`$0A31`); **this is the message drawn on** (R-037). **`mode`** says how the chip would show the picture: `play` = the level's bands (upper set, fine scroll, 38 columns, lower set from raster 119, panel from 202), `ready` = the panel set over the whole screen, 40 columns, rows 7–8 in colours `$0A`/`$02` between rasters `$42` and `$82`, `flat` = the panel set over the whole screen and sprites 0–2 from the registers (the sequence after a level, the REWIND screen); **`state`** = where the main loop stands (`play`, `ready`, `restart`, `sequence`, `rewind`, `ending`); `score` = the six digits `$338B` as a number, `lives` = `$281D`; **`events`** = the rules' events since the last message (`{kind, frame, a}`: `death`, `ready`, `fire`, `restart`/`checkpoint`, `mainLoop`, `levelEnd`, `sequence`, `load`, `levelInit`, `gameOver`, `rewind`, `ending`); **`over`** = the original would wait for the tape (PLEASE REWIND TAPE) or reset the machine (the ending after level 8) — the worker stops its own clock and the model goes to the game-over screen. `screen` is Screen RAM `$CC00`–`$CFFF` (1024 bytes: rows 0–18 the level, 19–24 the panel — **from M5 the loader draws the panel from the worker**, not from the template, `$CFF8` the sprite pointers), `color` Color RAM `$D800` (1000 bytes), `fine` is `$020C`, `fineY` `$020B`, `pointer` `$0201/$0202`, `running` `$0221`, `reg64` `$64`; `vic` is `$D000`–`$D02E` (sprites 0–2 = the Force and the ship; 3–7 the multiplexer; `$D016`/`$D018`/`$D021`–`$D023` as the handlers write them), `sprites` is the RAM under the I/O `$D000`–`$D2FF`, `glyphDD` the glyph `$DD` of the shared set; `lifeOver` = READY began, `gameOver` = the lives ran out, `levelOver` = the level ended (`$5E17`); **`bands`** = the three groups of the multiplexer's sprites 3–7, **`boss`** = the boss's rows, **`high`** = the worker's `$A000`–`$FFFF` (the level's set copied to `$C000` by the routine `$11FA`, the lower set and the level's sprites from `$E000`, the level code's drawings — **from M5 the loader composes the sets from it**, so the stars and the glyph animations move), only when it changed and in the first frame; **`sid`** (M6) = the stores into the SID in this frame, `[[cycle, register, value], …]` in the original's order — what the player `$6370` (in the 202 handler, in the READY and sequence iterations), `$6373` (the end of the sequence) and `$5E69` (`$D418` ← 0 after GAME OVER) wrote; `cycle` is the place in the frame (0–19 655, **the cadence model**, `Ship.MUSIC_LINES`: the 202 handler ≈ line 204, READY `$43`, sequence `$FA`); only when there was a store; **`sidRoles`** (R-055) = the changes of the SID voice roles in this frame, `[[cycle, voice 0–2, role], …]` — role 1 = an effect started on the voice (`$6544`), 0 = the effect ended (`$6622`) or the tune took the voice back (`$649B`, `$6476`); **it is not a store into the chip** (`matchsound` does not see it), the main thread sends it to the 6581 model as pseudo-register `$20`+voice and the model scales the voice by the MUSIC or SOUNDS slider; only when there was a change |
| `random` | `value` | the answer to `random`, 0–255 |
| `continued` | `level`, `frame` | ★ the answer to `continue`: the game goes on (READY in the next frame) |
| `continueFailed` | — | ★ the answer to `continue` when the world is not standing on the REWIND screen |
| `sample` | `kind`, `frames` | the answer to `sample`: `[[[cycle, register, value], …], …]`, frame by frame |

`tools/runworker.mjs` measures it without a browser; the scroll against the
original `tools/matchlevels.mjs`, the ship and weapons `tools/matchship.mjs`,
the enemies and bosses `tools/matchenemies.mjs`, the rules around the level
`tools/matchrules.mjs`, the sound store by store `tools/matchsound.mjs`; the
fingerprint against the previous run `tools/regress.mjs` (from M6 the SID
stores' fingerprint too).
